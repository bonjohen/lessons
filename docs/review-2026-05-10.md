# Project Review

**Date:** 2026-05-10
**Scope:** Full
**Project:** Lessons Hub (Astro static site + FastAPI RAG backend)
**Reviewer:** Claude Code

## Executive Summary

The project is structurally sound with clean dependency graphs, proper secret handling, and a well-organized adapter pattern. The two most significant findings are **unsanitized innerHTML rendering of backend data** in two frontend pages (XSS risk) and **50% of backend modules lacking dedicated test coverage**. The recent V2 hardening work (9 phases, 18 requirements) improved configuration, concurrency, and observability, but introduced some duplicated cache logic and left documentation out of sync with the new test count.

## Findings

### [HIGH] F-01: XSS via unsanitized innerHTML from backend data

**Category:** Security
**Evidence:**
- `src/pages/candidate-lessons.astro:32-42` — `listEl.innerHTML` renders `todo.title`, `todo.notes`, and `todo.source_project_url` from the `/api/todos` endpoint without sanitization
- `src/pages/gaps.astro:41-53` — `listEl.innerHTML` renders `gap.normalized_topic`, `gap.trigger_query`, `gap.gap_type`, and `gap.retrieval_summary` from the `/api/gaps` endpoint without sanitization
- By contrast, `src/pages/lessons/[id].astro:19-28` correctly sanitizes markdown with `sanitize-html` before `set:html`

**Impact:** An attacker who can write to `data/gaps/corpus-gaps.json` or inject malicious data through the gap detection pipeline can execute arbitrary JavaScript in any user's browser viewing these pages.
**Fix:** Import `sanitize-html` and sanitize all backend-supplied strings before inserting into `innerHTML`. Alternatively, use DOM APIs (`textContent`, `createElement`) instead of template literals for user-facing data.

### [HIGH] F-02: 50% of backend modules lack dedicated test coverage

**Category:** Tests
**Evidence:**
Modules with no corresponding test file:
- `backend/app/logging_config.py`
- `backend/app/metrics.py`
- `backend/app/rag/prompt_builder.py`
- `backend/app/models/schemas.py`
- `backend/app/adapters/llm/ollama_adapter.py`
- `backend/app/adapters/llm/bedrock_adapter.py`
- `backend/app/adapters/llm/azure_openai_adapter.py`
- `backend/app/adapters/llm/vertex_adapter.py`
- `backend/app/adapters/vector/opensearch_adapter.py`
- `backend/app/adapters/vector/azure_search_adapter.py`
- `backend/app/discovery/candidate_scorer.py`
- `backend/app/discovery/lesson_extractor.py`
- `backend/app/discovery/repo_intake.py`
- `backend/app/discovery/todo_writer.py`

Some are exercised indirectly through integration-style tests (e.g., cloud adapters via `test_aws_adapters.py`), but many have zero path coverage.

**Impact:** Regressions in untested modules are invisible until production. The adapter layer is particularly risky since cloud deployments rely on code that only runs through mock-heavy tests.
**Fix:** Prioritize tests for `candidate_scorer.py`, `lesson_extractor.py`, `repo_intake.py`, and `todo_writer.py` (discovery pipeline). Cloud adapters have mock-based tests in `test_aws/azure/gcp_adapters.py` which provide some coverage.

### [MEDIUM] F-03: Duplicated cache logic in retriever and generator

**Category:** Architecture
**Evidence:**
- `backend/app/rag/retriever.py:30` and `backend/app/rag/generator.py:30` — identical cache key construction: `cache_key = query if filters is None else f"{query}|{sorted(filters.items())}"`
- Both files duplicate the full TTL check + LRU eviction pattern (lines ~32-37 and ~74-77 in each)

**Impact:** If caching logic changes (TTL format, eviction policy, key format), both files must be updated in lockstep or they diverge silently.
**Fix:** Extract a `TTLCache` class into `backend/app/rag/cache.py` with `get()`, `put()`, and configurable TTL/max-size. Both retriever and generator instantiate it.

### [MEDIUM] F-04: Documentation lists wrong test count

**Category:** Documentation
**Evidence:**
- `CLAUDE.md:50` — states "Backend tests (71)" but actual count is 95
- `README.md:109` — same stale count
- `docs/v2_summary.md:4` — states "Total tests: 147 (71 backend + 76 project)"

**Impact:** Misleading for contributors and CI debugging. Stale counts erode trust in documentation accuracy.
**Fix:** Update all three files to reflect the current count (95 backend tests, 171 total).

### [MEDIUM] F-05: Unused Astro component (CorpusGapNotice)

**Category:** Dead Code
**Evidence:**
- `src/components/CorpusGapNotice.astro` exists but is never imported by any page or component
- Grep for `CorpusGapNotice` across `src/` returns zero matches outside its own file

**Impact:** Dead code adds confusion. A contributor might try to modify it thinking it's used.
**Fix:** Delete `src/components/CorpusGapNotice.astro` or integrate it into `ChatPanel.astro` as originally intended (per its internal comment).

### [MEDIUM] F-06: assert True tautology in test_discovery.py

**Category:** Tests
**Evidence:**
- `backend/tests/test_discovery.py:142` — `assert True` with comment "Verified by code review: no subprocess git push/pr commands"

**Impact:** This test can never fail. It provides false confidence that no auto-PR behavior exists. If someone adds `subprocess.run(["git", "push"])`, this test still passes.
**Fix:** Replace with an actual assertion: grep the source files for `git push` or `subprocess` calls, or delete the test entirely.

### [MEDIUM] F-07: Silent exception swallowing in Azure adapter

**Category:** Consistency
**Evidence:**
- `backend/app/adapters/vector/azure_search_adapter.py:72` — `except Exception: pass` on index creation failure
- `backend/app/adapters/vector/azure_search_adapter.py:194` — `except Exception: pass` on index deletion failure

**Impact:** If index creation fails silently, subsequent queries fail with cryptic errors. No log trail to diagnose the root cause.
**Fix:** Add `logger.warning("Index creation failed", exc_info=True)` instead of bare `pass`. Consistent with the pattern used in `_deps.py:63`.

### [MEDIUM] F-08: No schema validation on JSON file loads

**Category:** Architecture
**Evidence:**
- `backend/app/rag/gap_store.py:36-37` — `json.load()` without validating against `GapRecord` schema
- `backend/app/discovery/todo_writer.py:59,76` — `json.load()` without validation
- `backend/app/discovery/repo_intake.py:57` — candidate repos JSON loaded without schema check
- `backend/app/api/health.py:25` — `rag-chunks.json` loaded without structure validation

**Impact:** Corrupted or malformed JSON files cause runtime errors deep in call stacks instead of failing fast with clear messages.
**Fix:** Add Pydantic `model_validate()` calls after `json.load()` for gap_store and todo_writer. Health endpoint should wrap in try/except with graceful degradation.

### [MEDIUM] F-09: CLAUDE.md references non-existent file

**Category:** Documentation
**Evidence:**
- `CLAUDE.md:15` — references `docs/v2_suggestions_pdr.md` but the actual file is `docs/v2_suggestions_prd.md` (letters transposed: "pdr" vs "prd")

**Impact:** Contributors following CLAUDE.md can't find the referenced document.
**Fix:** Correct the filename to match the actual file on disk.

### [LOW] F-10: Missing defensive .gitignore entries

**Category:** Operations
**Evidence:**
- `.gitignore` lacks entries for `.vscode/`, `.idea/`, `*.swp`, `.DS_Store`, `Thumbs.db`
- No such files are currently tracked, but they're not protected against accidental commits

**Impact:** Low — a contributor could accidentally commit IDE config files.
**Fix:** Add standard editor/OS entries to `.gitignore`.

### [LOW] F-11: Missing Content Security Policy

**Category:** Security
**Evidence:**
- `src/layouts/BaseLayout.astro` — no `<meta http-equiv="Content-Security-Policy">` tag
- `astro.config.mjs` — no CSP middleware or header configuration

**Impact:** No defense-in-depth against XSS. If sanitization is bypassed (F-01), CSP would be the fallback.
**Fix:** Add a CSP meta tag to `BaseLayout.astro` restricting `script-src` and `style-src` to same-origin.

### [LOW] F-12: Gap detection thresholds not env-configurable

**Category:** Architecture
**Evidence:**
- `backend/app/rag/gap_detector.py:19-29` — five named constants (`MIN_RELEVANCE_THRESHOLD`, `MIN_DISTINCT_LESSONS`, etc.) are hardcoded with no env var override
- Compare with `retriever.py:12-13` where `CACHE_TTL_SECONDS` and `CACHE_MAX_SIZE` ARE configurable via env vars

**Impact:** Different deployments (e.g., smaller corpus vs. large corpus) may need different sensitivity thresholds. Currently requires code changes.
**Fix:** Add `os.environ.get()` fallbacks for each threshold, matching the pattern in `retriever.py`.

### [LOW] F-13: Metrics not exercised in CI

**Category:** Operations
**Evidence:**
- No CI workflow includes `pip install -e backend[metrics]`
- `prometheus_client` is not available during CI test runs
- `test_metrics_and_versioning.py:18-23` conditionally skips metrics assertions when unavailable

**Impact:** The metrics middleware and `/metrics` endpoint are never tested in CI with `prometheus_client` installed. Regressions would only surface in production.
**Fix:** Add `pip install -e "backend[dev,metrics]"` to `build-deploy.yml` install step, or accept as intentional (metrics are optional).
